FAQ


            

              What is BonesAI, and is it private?
              
A local-first AI app for your Mac. The model runs on your hardware via llamafile — every chat, search, and redaction stays on this machine. The single exception is the Claude cannon (Work → Send to Claude), which deliberately reaches Anthropic's API, and only with material you've redacted first.

            


            

              What's the difference between Chat, Work, Absorb and Brain?
              
Chat is everyday conversation with the local model. Work is for analysing one or more documents — summarise, find related content, redact and fire at Claude. Absorb turns documents into Memory entries Bones uses in every future conversation. Brain is your saved notes — outputs you've kept for later (summaries, Claude replies, etc.).

            


            

              How do I use Brain?
              
Brain is your saved-outputs scrapbook. Anywhere Bones produces something worth keeping — a summary in Work, Claude's reply to a cannon prompt, a compact digest — there's a Save to Brain button. Click it and the output lands in the Brain tab with the source file it came from.

              
Open the Brain tab to scroll through everything you've saved. Each note shows the title, timestamp, the body text, and which file(s) it was about. The Delete button on each note removes it.

              
Brain is for reference, not for the model — notes are not injected into chats. If you want something the model uses every time, put it in Memory instead. Brain data lives in ~/Library/Application Support/BonesAI/notes.json.

            


            

              Memory vs Brain — what's the difference?
              
Memory is injected into every local-model chat as standing context. It's what Bones “knows” about you and your work. Limited to ~4,000 characters so it doesn't eat the context budget.

              
Brain is a passive store of saved outputs you can browse. Not injected into chats — it's for reference, not for the model.

            


            

              How do I switch models (e.g. from Qwen to Saul)?
              
Settings → Available models → click Make active on the model you want. The server restarts on the new model in a few seconds. The status pill bottom-left of the sidebar shows which model is currently running.

            


            

              Why does one model run slower than another?
              
Bigger models (more parameters) need more compute per token, and the 2019 i9 / 2014 MBP runs everything on the CPU. Qwen 7B will be roughly 6-7 tokens/sec; a 14B model would be 1-2 tokens/sec — fine for a one-off summary, painful for live chat. Saul 7B is similar speed to Qwen 7B since they're the same size class.

            


            

              What's the context window for, and what should I set it to?
              
Context window = how much text the model can hold in mind at once (input + reply). Bigger = handles longer documents but uses more RAM and is slower per token. Defaults: 16K on 16+ GB Macs, 4K on 8 GB. Tune in Settings → Performance. 32K is doable on this i9 but worth it only for genuinely long jobs.

            


            

              How does Absorb actually work? Is it “training” the model?
              
No — true fine-tuning needs Apple Silicon or a GPU. Absorb runs the local model over the documents, extracts the load-bearing facts as discrete sentences, and you review which to keep. The kept ones go into Memory. From your point of view Bones “learns” the document; under the hood it's structured context, fully reversible (delete any Memory entry to forget it).

            


            

              What does Redact do, and can I trust it?
              
Redact replaces people's names, company names, addresses, emails, phones, and postcodes in your material with placeholders like [PERSON_1]. Two passes: deterministic regex (titled people, companies with legal suffixes, etc.) + an optional local-model scan for plain names the regex misses. Always review the editable redacted box before clicking Send to Claude — it's the safety net for anything that slips through.

            


            

              What happens when Claude replies? Do I see real names again?
              
Yes. Bones remembers which placeholder maps to which real entity in memory only (never on disk) and swaps them back into Claude's reply automatically. Toggle between the redacted and re-identified views with the button under the response. The map is wiped when you redact a new document or quit the app.

            


            

              How do I open BonesAI on my iPhone?
              
Settings → Sharing → tick Enable web server, set Scope to Local network, copy the URL. Open in Safari on the iPhone (must be same Wi-Fi or Tailscale). Add to Home Screen for a real fullscreen app experience. Some features (Work, Absorb, model management) are host-only — the phone is best for Chat and viewing Brain.

            


            

              How does iCloud Memory sync work?
              
Settings → Memory → tick Store memory in iCloud Drive. The Memory file moves to iCloud Drive/BonesAI/memory.json. Every Mac you install BonesAI on reads the same file, so what you teach on one machine appears on the others. The file is also visible in the Files app on iPhone/iPad. Only this small JSON syncs — model files stay local on each Mac.

            


            

              How do I install BonesAI on another Mac?
              
Download the latest release zip from the BonesAI GitHub. Right-click the app the first time → Open (to bypass Gatekeeper). The model file (4-9 GB) downloads on first launch. Turn on iCloud Memory sync and the new Mac inherits everything you've taught Bones already.

            

          


          

            
Troubleshooting


            

              Server error / model won't start
              
Settings → Diagnostics → Export log. The log shows exactly what llamafile said when it tried to load the model. Common causes: file truncated mid-download (delete and re-download), file format unsupported by llamafile (try a different quant from another HF uploader), or out of RAM (drop the context window or pick a smaller model).

            


            

              Model download fails with HTTP 401 or 403
              
The HuggingFace repo requires login or terms acceptance. Either use a different ungated uploader (TheBloke, bartowski, mobeetle), or download the GGUF manually from the HF page in Safari, drop it into ~/Library/Application Support/BonesAI/models/, and use Re-scan models folder in Settings.

            


            

              iPhone can't reach BonesAI over Wi-Fi
              
Confirm both devices are on the same network (not a Guest Wi-Fi with isolation). Check the URL in Settings → Sharing matches the one you opened on the iPhone. macOS firewall may need to allow incoming connections — System Settings → Network → Firewall. For "from anywhere" access, install Tailscale on both — then the Tailscale URL works over the encrypted mesh.

            


            

              Chat with Claude says "no API key"
              
Settings → Claude API → paste an Anthropic API key (sk-ant-…) and Save. Key lives in config.json on this Mac only (mode 0600, owner-readable only) and is never logged.

            


            

              Where is my data stored?
              
~/Library/Application Support/BonesAI/ on macOS. Contains config.json, chats/, notes.json (Brain), models/ (GGUF files), runtime/ (llamafile binary), and memory.json (unless on iCloud). Delete that whole folder to reset everything.

            

          


          
Hit a problem not listed here? Settings → Diagnostics → Export log, and send the .txt file.
